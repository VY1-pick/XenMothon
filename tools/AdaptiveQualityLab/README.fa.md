# آزمایشگاه مستقل انتخاب تنظیمات

این ابزار مسیر انتخاب گزینه، سقف Economy، محدودیت منابع، مدل محلی هزینه، جبههٔ پارتو، انتخاب کیفیت نزدیک به بهترین و کم‌مصرف‌تر، آزمون دوباره و ثبت نتیجه را اجرا می‌کند. هیچ پروژه، تنظیمات، Tray یا والپیپر برنامه را تغییر نمی‌دهد. نمونه‌های native موجود فقط هنگام build به‌صورت read-only در ابزار مستقل کامپایل می‌شوند؛ خود برنامه اجرا نمی‌شود.

دو نوع ورودی دارد:

1. سناریوهای مصنوعیِ صریح برای تست منطق تصمیم‌گیری: سیستم قوی، Economy ضعیف، گلوگاه دیکود، نبود شمارنده GPU، باتری و بار آلوده.
2. ویدیوی واقعی: فرایند جدا برای هر گزینه، Media Foundation، رندر واقعی D3D11، TimestampDisjoint، مصرف CPU فرایند، حافظه و بودجهٔ واقعی DXGI. شمارندهٔ استفادهٔ واقعی موتور GPU موجود نیست؛ زمان رندر GPU فقط proxy است و به درصد مصرف تبدیل نمی‌شود.

## اجرا

از PowerShell در ریشهٔ workspace:

```powershell
./tools/AdaptiveQualityLab/Run-Lab.ps1 -Video 'C:\path\video.mp4'
```

برای قفل Economy، `-Economy` اضافه کن. اگر سیستم مشغول باشد، پیش‌فرض Deferred است. برای صرفاً مشاهدهٔ رفتار زیر بار، `-ObserveBusy` اضافه کن؛ نتیجه Contaminated/Provisional خواهد بود و کانفیگ قطعی دستگاه نیست. `Ctrl+C` سنجش را متوقف می‌کند.

اجرای CLI بدون بازکردن مرورگر:

```powershell
python -B tools/AdaptiveQualityLab/lab.py --video 'C:\path\video.mp4' --economy
python -B tools/AdaptiveQualityLab/lab.py
python -B tools/AdaptiveQualityLab/test_lab.py
```

برای آزمایش سیاست متفاوت، `--ram-budget-mib 1024` را به CLI اضافه کن. این تغییر **صریح و آزمایشی** در `policyOverrides` ثبت می‌شود؛ سقف پیش‌فرض RAM مقیم min(1024 MiB, 25% RAM آزاد) است؛ گزینهٔ CLI سقف صریح کاربر را ثبت می‌کند. Commit خصوصی مستقل، با سقف min(2048 MiB, 25% ظرفیت تعهد آزاد) کنترل می‌شود.

ساخت مستقل probe (نیازمند .NET SDK؛ فایل ساخته‌شده self-contained است):

```powershell
dotnet publish tools/AdaptiveQualityLab/NativeProbe/NativeProbe.csproj -c Release -r win-x64 --self-contained true -o artifacts/adaptive-quality-lab/probe
```

خروجی در `artifacts/adaptive-quality-lab/report.html` و `results.json` است؛ گزارش بدون اینترنت باز می‌شود و انتخاب سناریو، نمودار، جدول دلایل رد، جزئیات هر گزینه و خروجی JSON دارد. request/probeهای خام در همان پوشه برای بازتولید نگهداری می‌شوند؛ requestها حاوی مسیر محلی ویدیو هستند و نباید بدون بررسی منتشر شوند. فایل ویدیو تغییر نمی‌کند. وابستگی optimizer فقط Python standard library است.

## حدود این نمونهٔ اجرایی

**این ابزار نمونهٔ اجرایی هستهٔ انتخاب است؛ تمام بخش‌های سند ۱۷مرحله‌ای را پیاده‌سازی نمی‌کند.**

- surface آزمایش خارج از صفحه و به اندازهٔ نمایشگر اصلی است. GPU واقعاً رندر می‌کند، اما زمان نمایش روی پنل مشاهده نمی‌شود؛ نتیجهٔ native حداکثر Low/Provisional است.
- مسیر codec سخت‌افزاری قطعی تشخیص داده نمی‌شود؛ GPU-resident بودن خروجی ثبت می‌شود و با ثابت‌شدن hardware decode اشتباه گرفته نمی‌شود.
- کیفیت از سه فریم هم‌زمان در ۰،۱،۲ ثانیه، هرکدام 256×144، با SSIM محلی و ترکیب میانگین/بدترین بخش و نسبت FPS تخمین زده می‌شود؛ prior هندسی فقط برای پیشنهاد آزمایش بعدی است. این معیار MS-SSIM چندمقیاسی، حرکت واقعی چند بخش و ترجیح دیداری انسان نیست. خروجی باکیفیت‌ترین گزینهٔ همین معیار آزمایشی است، نه حکم قطعی کیفیت چشم انسان.
- نمونه‌ها در شروع فایل اجرا می‌شوند. دیکود تمام فریم‌های منبع حفظ می‌شود، حتی وقتی FPS نمایش کمتر است. فایل کوتاه با مدت نامعلوم پس از EOF با حفظ ساعت زمان‌بندی تکرار می‌شود؛ بازکردن دیکودر و اولین read از زمان‌سنجی پخش پایدار جدا هستند.
- کیفیت هندسی تا ابعاد نمایشگر سود دارد؛ رزولوشن منبع بیشتر از نمایشگر به‌تنهایی امتیاز اضافی نمی‌گیرد.
- CPUUpper بازنمونه‌گیری عملیاتی پنجره‌های یک‌ثانیه‌ای است؛ p95 GPU از queryهاست، نه wait روی EVENT. سربار query نیز در اجرای probe حضور دارد.
- سنجش تمام نمایشگرها به‌صورت مشترک، صوت، Resume، HDR، توان وات، تغییر زمینهٔ برق در میانهٔ سنجش و worker priority/installer هنوز آزموده نشده‌اند؛ در خروجی فهرست شده‌اند. AC به DC تعمیم داده نمی‌شود.
- جست‌وجو حداکثر ۱۲ آزمایش اصلی دارد؛ سپس تا دو تکرار طولانی، زیر سقف ۱۸۰ثانیه‌ای اجرا می‌شوند. timeout فرایند جدا، UI یا برنامهٔ اصلی را معطل نمی‌کند.
- گزینه‌ای که تأیید طولانی را رد کند دوباره از غربال به‌عنوان برنده برنمی‌گردد. نبود گزینهٔ تأییدشده NoBudgetFit است و به معنای پخش‌نشدن فایل یا ضعف دستگاه نیست. Applied/High تولید نمی‌شود.
- CLI نتایج را هر بار دوباره سنجیده و اتمیک ثبت می‌کند؛ cache خودکار در نصب و تعویض تنظیمات برنامه عمداً به این ابزار متصل نشده است.

مستند طراحی اصلی: `docs/engineering/adaptive-quality-algorithm.fa.md`.

## بازطراحی نسخهٔ ۲ — 2026-10-07

تفسیر قبلی PrivateBytes به‌عنوان RAM درست نبود؛ نتیجهٔ اجرای نسخهٔ ۱ برای تعیین توان دستگاه معتبر نیست. WorkingSet حافظهٔ مقیم پردازش است، PrivateUsage تعهد خصوصی است، و local/non-local GPU جدا ثبت می‌شوند؛ این اعداد به دلیل احتمال هم‌پوشانی جمع نمی‌شوند. مراحل بازکردن و گرم‌شدن هم در اوج حافظه لحاظ می‌شوند. [تعریف رسمی Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex).

تنظیم ذخیره‌شدهٔ برنامه فقط خوانده می‌شود و نخستین گزینهٔ غربال است؛ برابر بودن آن با تنظیم واقعاً فعال ادعا نمی‌شود. GPU timestamp شاخص زمان رندر است و در نبود busy counter، عبور آن صرفاً هشدار است. نویز زمان‌بندی غربال با رد آزمون طولانی یکسان نیست. بار زمینهٔ بالای سیستم نتیجه را غیرقطعی نگه می‌دارد.

خروجی اجرای نهایی در `artifacts/adaptive-quality-lab-v2-final/report.html` و `results.json` است. اسکریپت Run-Lab نیز همین پوشه را می‌سازد. ۲۶ بررسی رفتاری شامل تفکیک RAM/Commit و مرزهای مستقل آنها پاس شدند. معیار کیفیت، سنجش ادراکی کامل 4K نیست و تنها سه نقطهٔ آغاز فایل را پوشش می‌دهد. خام فریم‌ها در probe JSON برای بازتولید محلی باقی می‌ماند؛ برای اشتراک گزارش از خروجی تجمیعی استفاده شود.

### نتیجهٔ اجرای نهایی همین ویدیو

مرجع 2160p/30fps/100%/mip/shared هم غربال و هم ۲۴ثانیه اعتبارسنجی را گذراند. در اعتبارسنجی، RAM مقیم اوج 85.65 MiB، Commit خصوصی اوج 1153.92 MiB و submitMissRatio صفر بود. 1080p/30fps/100% نیز با RAM 85.39 MiB، Commit 975.48 MiB و submitMissRatio حدود 0.278% پذیرفته شد. امتیاز نمونه‌ای کیفیت 0.99870 در مقابل مرجع 1.0 بود؛ به دلیل پنل 1920×1080 و هزینهٔ نرمال‌شدهٔ کمتر، پیشنهاد موقت 1080p انتخاب شد. این عدد کیفیت تضمین حفظ جزئیات کامل 4K نیست.

CPU زمینه 28.91% بود؛ نتیجه Contaminated/Provisional است. این اجرا نشان می‌دهد رد کلی دستگاه در نسخهٔ قبلی درست نبود، نه اینکه همهٔ محتواها/نمایشگرها تأیید شده‌اند. هیچ تنظیمی در برنامه اعمال نشده است.

### قاعدهٔ نسخهٔ ۲٫۱: ابعاد مانیتور هنگام مصرف نزدیک

در فاصلهٔ 0.02 از بهترین کیفیت، اگر هزینهٔ کلی و تک‌تک نسبت‌های مصرف حداکثر 0.05 از بودجه با کم‌هزینه‌ترین گزینه فاصله داشته باشند، ابعاد مؤثر هماهنگ با پنل اولویت دارد. رزولوشن منبع، renderScale و نسبت تصویر لحاظ می‌شوند و Economy قفل می‌ماند. ۳۳ بررسی رفتاری پاس شدند؛ از جمله پنل 720 و 1080، منبع کوچک‌تر، scale پایین، جهش CPU و رد بودجه.

گزارش اجرای قبلی با همان دادهٔ ثبت‌شده دوباره انتخاب شده و decisionVersion مشخص است؛ این بازانتخاب اجرای تازهٔ ویدیو محسوب نمی‌شود. برای سنجش جدید Run-Lab.ps1 را اجرا کن. نتیجهٔ کاربردی این دستگاه در آزمون فعلی: هر دو حالت 2160p/30 و 1080p/30 از بودجه و معیار ارسال فریم گذشتند؛ پیشنهاد پنل 1080 فعلی 1080p/30 است. این تأیید محدود به همان معیارهای ابزار است؛ بار CPU دیگر برنامه‌ها حدود 29% بود و زمان نمایش واقعی پنل/صوت اندازه‌گیری نشده است.
